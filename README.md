# 躲B球辦事處網站

- **前台 `index.html`**：任何人都能看公告欄，頁首右上角有「進入後台」按鈕；左上角的名稱只是文字，點了不會有動作。每則公告底下可以留言（不用登入，只要填暱稱）。「網站設定」裡填的內容會顯示在前台：標語與歡迎文字是頁首下方的**跑馬燈**，服務窗口、辦事須知、辦公時間與連結、頁尾文字在網頁最下方的**深藍色頁尾**（沒填的區塊不會出現）；也可以設定整頁的網站背景（見下方「網站設定與網站背景」）。
- **後台 `admin.html`**：輸入帳號與密碼登入，管理公告、待辦事項、圖片牆與網站設定。公告管理、待辦事項、圖片牆三個分頁都是「現有內容的列表在最上面、新增表單在下面」；左上角的名稱同樣只是文字。
  - **公告管理**：新增／編輯／發布／置頂／刪除公告，每則公告可以個別關閉留言；按「留言」可以看讀者留言、以群主身分回覆（前台會顯示「群主」標章）、刪除不當留言。
  - **批次匯入**：公告管理分頁的「批次匯入公告」可以上傳 JSON 檔，一次新增多則公告（格式見下方）。
  - **待辦事項**：只有登入後台的人看得到（前台讀者看不到）。可以勾選完成、編輯、刪除，每項待辦底下也能留言討論。
  - **新增提示**：「待辦事項」分頁左上角的紅色圓圈，顯示你上次查看之後別人新增了幾則待辦；進入待辦分頁就消失。看過的時間記在這台瀏覽器，換瀏覽器或清除瀏覽資料後會重新計算（第一次使用時，既有待辦都算看過）。
  - **時間**：待辦與公告的日期後面會顯示儲存時間 `時:分:秒`（24 小時制，用瀏覽器所在時區）；後台列表和前台公告欄都有。
  - **署名**：後台上方可以填署名，新增待辦與回覆時會附上；只記在你這台瀏覽器，不填就署名「群主」。

## 為什麼要 GitHub + Firebase 一起用

- **GitHub Pages** 只能放靜態網頁，不能儲存資料，也沒有登入功能。
- **Firebase** 補上這兩樣：Firestore 存公告，Authentication 驗證帳號密碼。
- 帳號密碼**不能**寫在網頁程式裡比對：GitHub Pages 是公開的，任何人檢視原始碼都看得到。所以密碼只存在 Firebase，由 Firebase 伺服器驗證，程式碼和這份資料夾裡都不會出現密碼。
- 真正的鎖在 `firestore.rules`：只有管理員帳號的 UID 寫得進去，別人就算打開 `admin.html` 也改不了任何東西。

兩邊在免費方案內就夠用（Firebase 用 Spark 方案，不需要綁信用卡）。

## 設定步驟

### 1. 建立 Firebase 專案

1. 到 [Firebase 控制台](https://console.firebase.google.com/) 建立專案（Google Analytics 可以不開）。
2. 專案首頁點 **網頁 `</>`** 新增應用程式，取得 `firebaseConfig`。
3. 把 `apiKey`、`authDomain`、`projectId`、`appId` 貼進 `js/firebase-config.js`。

### 2. 開啟帳號密碼登入並建立管理員

1. **Authentication → Sign-in method**，啟用 **電子郵件／密碼**（只開這一個，不用開「電子郵件連結」）。
2. **Authentication → Users → 新增使用者**：
   - 電子郵件：`帳號@bball-office.example.com`。帳號改成小寫後直接接上網域，例如帳號 `dodgeBball`（d-o-d-g-e-**b-b**-a-l-l）就填 `dodgebball@bball-office.example.com`。這個信箱不需要真的存在。
   - 密碼：設成你要用的密碼。
   - 後台登入時只要輸入帳號（不分大小寫）和密碼，程式會自己補上信箱網域。網域在 `js/firebase-config.js` 的 `adminEmailDomain`，改了的話建立使用者時也要同步改。
   - 相容舊說明：早期說明曾把信箱寫成 `dodgeball@…`（少一個 b）。已經照那個建立的話不用重建，`firebase-config.js` 的 `emailAliases` 讓兩種拼法都能登入。
3. 建立後，在使用者清單複製這個帳號的 **使用者 UID**，下一步要用。
4. **Authentication → 設定 → 授權網域**，加入 `你的帳號.github.io`（`localhost` 預設已授權）。

### 3. 建立資料庫並發布規則

1. **Firestore Database → 建立資料庫**，位置選 `asia-east1`（台灣），模式選正式版。
2. 到 **規則** 分頁，貼上 `firestore.rules` 的內容（整份取代舊的）。
3. 這份檔案裡的管理員 UID 已經填好；如果換了管理員帳號，把 `request.auth.uid ==` 後面的字串換成新的使用者 UID。按 **發布**。

> 新增留言與待辦功能後，**規則一定要重新貼上並發布**，否則留言和待辦會顯示「沒有權限」。
> 留言與待辦用到的查詢都只依單一欄位排序，Firestore 會自動建立索引，不需要手動建索引。

### 4. 放上 GitHub Pages

1. 建立 GitHub 儲存庫，上傳這個資料夾裡的所有檔案（保持 `css/`、`js/` 資料夾結構）。
2. **Settings → Pages → Build and deployment**，來源選 `Deploy from a branch`，分支選 `main`、資料夾選 `/ (root)`。
3. 幾分鐘後網站會出現在 `https://你的帳號.github.io/儲存庫名稱/`。

### 5. 第一次使用

1. 在前台點右上角的 **進入後台**，輸入帳號與密碼。
2. 先到 **網站設定** 填名稱、歡迎文字、服務窗口、辦事須知、連結，按 **儲存設定**。
3. 再到 **公告管理** 新增第一則公告。公告編號 NO. 會自動遞增。

## 在自己電腦預覽

瀏覽器不允許直接雙擊開啟 `file://` 的 ES 模組，要用本機伺服器：

```
python -m http.server 8000
```

然後開 `http://localhost:8000`。還沒填 `firebase-config.js` 時，前台會顯示範例內容，方便先看版面。

## 注意事項

- `apiKey` 等設定值本來就會出現在網頁原始碼裡，不是密碼；不要把它當成機密，但也不要為了「保護」而省略規則。
- 規則用 UID 判斷管理員。就算有人用 Firebase 的公開介面自己註冊帳號，也拿不到寫入權限。
- 要換密碼：Firebase 控制台 → Authentication → Users → 該帳號 → 重設密碼；不用改任何程式。
- 公告分類固定為 公告／活動／須知／緊急。要改分類，`js/text.js` 的 `CATEGORIES`、`admin.html` 的選項、`firestore.rules` 的清單三處要一起改。
- 免費額度以 Firebase 官方方案頁為準；一般社群公告頁的讀寫量遠低於額度。前台只會讀「展開中」公告的留言，用來節省讀取次數。

## 更新網站後，畫面怪怪的（卡在「載入公告中…」、版面亂掉）

最常見的原因是**新的網頁配到舊的程式或樣式**：瀏覽器會把 `js`、`css` 檔案暫存約 10 分鐘，按一般的重新整理只會重新抓網頁本身。

- 為了避免這種情況，`index.html` 和 `admin.html` 裡每個 `css`、`js` 的網址都帶了版本代碼（`?v=` 後面那串英數字，`js` 之間互相引用的網址由網頁上的 `importmap` 補上同一個代碼）。**只要有任何一個 `js` 或 `css` 檔案改了，代碼就會換**，瀏覽器就一定會抓新檔。代碼是我每次出新版本時依檔案內容自動算好、寫進這兩個網頁的，直接整包上傳就行。
- 如果你自己手動改了 `js` 或 `css` 檔案，請把兩個 `.html` 裡所有的 `?v=` 後面的字串換成任何新的英數字（用編輯器的「全部取代」一次換掉），否則訪客最多 10 分鐘內還會看到舊的。
- 太舊的瀏覽器（iOS 與 Safari 16.3 以前、Firefox 107 以前）不認得 `importmap`，會照舊方式載入，功能不受影響，只是少了這層保護。
- 還是卡住時：先按 `Ctrl + F5`（手機可以用無痕分頁開）；再到 GitHub 專案確認 `js`、`css` 資料夾裡的檔案**都**換成新版了（可以點開 `js/public.js` 看日期與內容）。上傳時請整包覆蓋，不要只換幾個檔案。
- 網站設定的顯示出錯時，公告不會被擋住：公告照常載入，錯誤只會記在瀏覽器的主控台（F12）。

## 批次匯入公告（JSON）

後台 → 公告管理 → **批次匯入公告**，選擇 `.json` 檔後會先顯示預覽，確認無誤再按「確認匯入」。可以請 Claude 把你貼的文字轉成這種檔案，範例見 `announcements-example.json`。

```json
{
  "announcements": [
    { "title": "標題", "body": "內文，換行用 \n", "category": "公告", "pinned": false, "published": true, "commentsOpen": true }
  ]
}
```

| 欄位 | 必填 | 說明 |
| --- | --- | --- |
| `title` | 是 | 標題，1–120 字 |
| `body` | 否 | 內文，最多 5000 字，預設空白；網址會在前台自動變成連結 |
| `category` | 否 | `公告`／`活動`／`須知`／`緊急`，預設 `公告` |
| `pinned` | 否 | 是否置頂，`true` 或 `false`（不加引號），預設 `false` |
| `published` | 否 | `false` 會存成草稿，前台看不到，預設 `true` |
| `commentsOpen` | 否 | 是否開放讀者留言，預設 `true` |

- 最外層可以是 `{ "announcements": [ … ] }`，也可以直接是 `[ … ]`。一次最多 100 則、檔案最大 2 MB。
- 公告編號依檔案裡的順序接在現有編號後面，**最後一則編號最大，會顯示在最上面**。想要某則排在最上面，就放在檔案最後。
- 預覽畫面會標出「標題與現有公告相同」的項目，預設略過，避免同一份檔案上傳兩次造成重複。
- 檔案裡只要有一個項目格式不對，整份都不會匯入，並指出是第幾則；寫入時也是全部成功或全部失敗，不會只匯入一半。
- 匯入的是公告本身；日期以匯入當下為準。想保留原本日期，請寫在內文裡。
- 這個功能不需要改資料庫規則。

## 網站設定與網站背景

後台 → **網站設定** 分頁，上面是「網站背景」，下面是文字設定。文字設定存在資料庫的 `site/settings`，欄位：`officeName`（網站名稱）、`tagline`（標語）、`welcome`（歡迎文字）、`windows`（服務窗口）、`rules`（辦事須知）、`hours`（辦公時間）、`links`（相關連結）、`footer`（頁尾文字）。每個欄位按「儲存設定」就會顯示在前台，沒填內容的區塊整塊不會出現。

前台各處顯示什麼：

- **頁首左上角**：網站名稱（純文字）；名稱同時是瀏覽器分頁標題，也有一個看不見的 `h1` 給螢幕閱讀器用。前台沒有藍色招牌方塊。
- **跑馬燈（頁首下方）**：標語排在前面，歡迎文字每一行算一段，段與段之間留空白，文字由右往左一直循環捲動；兩個都沒填，跑馬燈整塊不顯示。捲動速度固定（約每秒 70 像素），文字越長捲一輪越久。訪客把滑鼠移上去或點一下（手機點一下）可以暫停，再點一下繼續；文字裡的網址會變成可點的連結。系統設定了「減少動態效果」的訪客不會捲動，整段文字直接顯示、需要時換行。
- **頁尾（網頁最下方，深藍底）**：依序是服務窗口、辦事須知、辦公時間與連結，最底下是頁尾文字（留空就顯示網站名稱）；沒填的區塊不會出現。

版面的開關在 `js/public.js` 開頭的 `LAYOUT`：`hero`（跑馬燈）、`extraSections`（頁尾裡的服務窗口、辦事須知、辦公時間與連結）、`footer`（整個頁尾；關掉的話頁尾裡的區塊也一起消失）目前都是開的；`called`（跑馬燈下方的「最新公告」叫號面板）不屬於網站設定，目前是關的，想開就改成 `true`。

### 網站背景

- 在「網站背景」選擇檔案（手機或電腦的圖片、GIF、MP4），上傳後預覽會立刻出現，調整「背景不透明度」（10–100%，預設 40%，數字越小越淡），按**儲存背景**才會生效；**移除背景**只會取消設定，不會刪掉檔案。
- 背景是固定在視窗後面的整頁底圖，圖片與影片會填滿整個視窗（超出的部分裁掉）。公告與圖片牆維持原本的樣子；跑馬燈有半透明的底，頁尾是不透明的深藍色，所以背景再花，文字都讀得清楚。
- MP4 當背景時**固定靜音、重複播放**；系統設定了「減少動態效果」的訪客，影片不會自動播放。背景圖片或影片載入失敗時會自動隱藏，不影響頁面。
- 上傳走的是和圖片牆同一套 GitHub 上傳（見下方），所以同樣要先設定一次 GitHub 專案與權杖、同樣要等一兩分鐘網站發布；發布前預覽會顯示「暫時載入不到」並自動重試。單檔上限 25 MB，背景是每位訪客一進網站就要載入的，建議圖片壓到 1 MB 以內、MP4 用幾 MB 的短片。
- 資料存在 `site/settings` 的 `bgUrl`、`bgKind`（`image`／`gif`／`video`）、`bgOpacity`（10–100）三個欄位；背景與文字設定分開儲存（用合併寫入），互不覆蓋。規則沿用 `site` 的設定（任何人可讀、只有管理員可寫），**不需要改規則**。

## 圖片牆（公告欄上方的輪播）

前台公告欄上方的大框，可以輪播圖片、GIF 與 MP4，下方有圓點可以手動切換。**一張都沒有（或全部停用）時，整塊不會顯示。**

### 怎麼放檔案

後台的「新增圖片或影片」只有一個「選擇檔案」按鈕，檔案一律從手機或電腦上傳（不再需要自己填檔案路徑或網址）。**第一次使用要先設定一次：**

1. 後台 → **圖片牆** → 按「選擇檔案」挑檔案時，如果還沒設定，下面的「從手機或電腦上傳檔案的設定（GitHub）」會自動打開。
2. 照畫面上的四個步驟，在 GitHub 建立一組 **fine-grained 權杖**：只選這個網站的專案、只開 **Contents：Read and write**，其他權限都不要開。
3. 把「帳號/專案名稱」與權杖貼進去，按「測試並儲存」，看到「連線成功」就完成。
4. 設定好之後，這整個設定區塊會自動收起來，檔案欄下面只剩一個小連結「更改上傳設定（GitHub 專案與權杖）」；要換專案或換權杖時點它就會重新打開。上傳時如果 GitHub 回報權杖失效或權限不足，設定區塊也會自動打開。
5. 之後只要在「新增圖片或影片」按「選擇檔案」，挑裝置上的圖片、GIF 或 MP4（手機上通常可以選相簿、檔案，或直接拍照／錄影），上傳完畫面會顯示已上傳，再按「儲存」就加進圖片牆了。編輯既有項目時，沒有重新選檔案就沿用原本的檔案。

運作方式與注意事項：

- 檔案會存進專案的 `media/` 資料夾（等於在你的專案裡新增一次提交），檔名會自動轉成英數字並加上時間，不會蓋掉舊檔。這個方式**不用任何付費方案**；Firebase 自己的 Storage 需要綁付款方式，所以沒用它。
- 單檔上限 25 MB，可上傳 JPG、PNG、GIF、WEBP、AVIF、MP4、WEBM、MOV（不收 SVG）。
- 用手機要注意：手機拍的影片很容易超過 25 MB，請先剪短或壓縮。iPhone 預設拍的照片是 HEIC 格式、影片是 HEVC 編碼，網頁大多無法顯示或播放，建議到「設定 → 相機 → 格式」選「最相容」，之後拍的就是 JPG 與 H.264 的 MP4。HEIC 檔案會被擋下並提示。
- 上傳後 GitHub Pages 要一兩分鐘才會發布。表單下方會顯示進度，變成「已上傳並發布」就代表前台讀得到了；發布前先按「儲存」也可以，前台會暫時顯示「圖片無法載入」。
- 權杖等同密碼。它只對你選的那一個專案有效，但 GitHub 的權限沒辦法限制到單一資料夾：拿到權杖的人**可以修改專案裡的任何檔案**（包含網站程式），不只是 `media/`。請不要貼給別人，也不要貼在這個後台以外的地方。
- 「記住權杖」預設是勾選的：權杖存在這台瀏覽器，下次不用重貼（換瀏覽器或換裝置才要再貼一次）。因為存在 `帳號.github.io` 這個網域底下，同一個 GitHub 帳號的其他 GitHub Pages 網站的程式也讀得到；公用或別人的手機、電腦請取消勾選，這樣權杖只留在目前分頁，登出或關掉分頁就消失。
- 權杖會過期（建立時可以選期限），過期後重新產生再貼一次即可；懷疑外流就到 GitHub 的權杖頁面直接刪除，它會立刻失效。
- 權杖不會寫進任何檔案、也不會傳到 Firebase；只有在你按「測試並儲存」或上傳檔案時，才由你的瀏覽器直接送給 GitHub。**不要把權杖直接寫進網頁程式裡來省去貼上的步驟**：這個網站是公開的，任何人按右鍵「檢視原始碼」就能看到，等於把專案的寫入權限送給所有人。

> 後台沒有手動填路徑或網址的欄位。程式本身仍然看得懂 `media/檔名.jpg` 這種專案內路徑與 `https://` 網址，所以資料庫裡的 `site/wall` 若已經有這類項目（或你到 Firebase 控制台自己加），照樣能顯示，也能在後台編輯其他欄位；只接受 `http://`、`https://` 與專案內的相對路徑，其他格式一律拒絕。

類型預設依副檔名自動判斷：`.mp4 .webm .m4v .ogv .mov` 是影片，`.gif` 是 GIF，其他當圖片。判斷錯了可以在表單的「類型」手動指定。動態 WebP、APNG 會被當成一般圖片，依停留秒數換下一張。

### 多久換下一張

| 類型 | 換下一張的時機 |
| --- | --- |
| 一般圖片 | 圖片載入完成後，停留表單「停留秒數」填的秒數（1–600 秒）；留空就用預設秒數（5 秒；表單的提示文字會顯示目前的預設值）。預設秒數不再有單獨的設定表單，要讓某張停留比較久，直接在那一張填秒數 |
| GIF | 讀取 GIF 檔內每一格的時間，播完一輪後再等 1 秒。單張填了秒數就改用該秒數 |
| MP4 等影片 | 播放結束後等 1 秒。影片不看秒數設定 |

- 只有一張時：圖片不會再換；影片播完等 1 秒後從頭重播。
- 瀏覽器分頁在背景時會暫停，切回來才繼續。
- 系統設定了「減少動態效果」的訪客：不自動播放、不自動換張，影片顯示瀏覽器原生控制列，需手動切換。
- GIF 的播放時間需要讀取檔案內容：放在自己專案 `media/` 裡一定讀得到；用外部網址時，對方網站必須允許跨網域讀取，否則改用停留秒數（沒填就用預設秒數）。外部網址不能從後台新增，這條只適用於資料庫裡本來就有外部網址的項目。

### 顯示期限（到期自動停止，或永久顯示）

每一張都有「顯示期限」，在後台新增或編輯時選：

- **永久顯示**（預設）：一直放著，直到你自己停用或刪除。
- **到指定時間自動停止顯示**：選一個日期與時間（以你目前使用的裝置的時區為準）。時間一到，前台就不再播放這一張；正開著網頁的訪客也會即時看到它消失，不用重新整理。

到期時的畫面行為：

- 到期的不是正在播的那張：輪播不受影響，圓點數量減少。
- 正在播的那張剛好到期：換成它後面的下一張。
- 所有張都到期了：整塊圖片牆消失；只剩一張時，就停在那一張。
- 訪客把分頁放在背景時，期間到期的張會在他回到分頁時一次清掉。

到期後的資料：

- 網站沒有伺服器可以定時去刪資料，所以到期的**只是不再顯示，設定還留在後台**。列表裡會標「已到期」、灰底，狀態列寫「共 N 張，前台顯示 M 張，已到期 K 張」。
- 要延長：編輯那一張，把時間改成未來的時間（或改成永久顯示）。
- 要真的刪掉：列表右上角的「清除已到期」一次刪掉所有已到期的（會先確認），或用單張的「刪除」。
- 新設的到期時間不能是過去的時間。編輯已到期的那張、沒動時間只改別的欄位，可以照常儲存。
- 到期是由訪客的瀏覽器依**訪客裝置的時鐘**判斷。裝置時鐘不準的人，可能提早或延後看到消失。
- 「到期」只是從輪播拿掉，不是把檔案藏起來：`media/` 裡的檔案仍然可以用網址直接打開。要讓檔案也消失，請到 GitHub 把它刪掉。

### 聲音按鈕

MP4 影片檔本身如果有聲音，放在圖片牆上就會有聲音。圖片牆右上角有喇叭按鈕（牆裡有影片時才會出現），點一下靜音、再點一下開聲音。

- 預設是**有聲音**，但手機與多數瀏覽器規定：訪客還沒操作過頁面時，不能自動播放有聲音的影片。碰到這種情況，影片會自動改成靜音播放，按鈕顯示靜音狀態，訪客點一下按鈕就會開聲音，之後的影片也維持有聲。這是瀏覽器規定，網頁無法繞過。
- 聲音狀態只在目前這次瀏覽有效，重新整理後回到預設。

### 圖片與影片的比例

- 圖片牆的外框固定是 16:9（電腦版最高 560 px，手機是整個寬度）。**16:9 的圖片或影片會剛好填滿**；其他比例（例如 9:16 的直式、1:1 的方形）會**完整縮小放進外框、不裁切、不變形**，多出來的地方是深色底。
- 直式內容在外框裡會比較小：9:16 只佔外框寬度的 31.6%（手機上大約 110 px 寬）。想讓畫面看起來滿版，請盡量準備 16:9 的橫式檔案。
- 後台列表的縮圖也是同樣的規則。

### 檔案大小與流量

- 後台上傳單檔上限 25 MB。（GitHub 本身對專案裡的單檔，50 MiB 以上會警告，**100 MiB 以上會被擋下**。）
- GitHub Pages 發布的網站總大小不能超過 1 GB，每月有約 100 GB 的軟性流量上限。影片會很快吃掉流量，建議壓成幾 MB 的短片（H.264 編碼的 MP4 相容性最好）。
- 一個圖片牆最多 30 張。

### 其他

- 圖片牆的內容存在資料庫的 `site/wall`（每張的欄位：`id, url, kind, alt, seconds, active, expiresAt`；`expiresAt` 是到期時間的毫秒數，`null` 是永久顯示），沿用「網站設定」的規則（任何人可讀、只有管理員可寫），**不需要改規則**。舊版沒有 `expiresAt` 的資料會當成永久顯示。
- 後台刪除只是從輪播移除，不會刪掉 `media/` 裡的檔案本身。
- 圖片牆的內容是一整份資料，兩個瀏覽器同時改會以最後存的為準，所以請不要同時在兩個地方編輯。

## 留言功能的限制

- 讀者留言**不用登入**，這是你要的設計，但也代表任何人都能送出留言。網頁裡的 20 秒冷卻和隱藏欄位只能擋手滑連按與簡單機器人，**擋不了**直接呼叫資料庫的人。
- 規則會確認：暱稱 1–20 字、內容 1–500 字、欄位固定、時間由伺服器填、讀者不能冒充群主、已關閉留言或草稿的公告不能留言、讀者不能修改或刪除留言。
- 被灌留言時：到後台刪除不當留言，或在公告上取消「開放讀者留言」（關閉後前台立刻不能留言）。
- 如果之後垃圾留言變多，可以再加 Firebase App Check（需要額外設定 reCAPTCHA），這版沒有加。
- 留言是公開的，前台表單有提醒讀者不要留下電話、住址等個人資料。
- 刪除公告或待辦時，底下的留言會一起刪除。
